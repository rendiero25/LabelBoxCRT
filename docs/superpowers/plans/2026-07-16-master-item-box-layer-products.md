# Master Item Box Layer Products Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (- [ ]) syntax for tracking.

**Goal:** Enable admins to select an owned Box Definition from a Master Item and maintain Product + Qty requirements one layer at a time.

**Architecture:** Retain the normalized graph: master_items -> box_definitions -> box_layers -> box_layer_requirements -> products. An admin-only RPC atomically owns mutation: it validates ownership, synchronizes master_item_products, validates the complete layer payload, replaces editable requirements, and appends audit logs. The Master Item page loads the graph and offers Box and Layer selectors.

**Tech Stack:** Next.js 16 App Router, React 19 useActionState, TypeScript strict, Supabase PostgreSQL RPC/RLS, pgTAP, Vitest, shadcn/ui, Sonner.

## Global Constraints

- Do not add a Box/Layer field to products.
- Preserve box_definitions.master_item_id ownership and clone-before-edit for used definitions.
- Permit 1-10 layers only; every layer requires distinct active Products and positive integer Qty.
- Browser has no direct DML to protected master tables.
- Mapping synchronization and requirement persistence are atomic and audited.
- Existing Box Definition editor must enforce the same 10-layer maximum.
